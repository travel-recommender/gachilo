# H4 실험용 화면 (혜인)

관련: [실험 설계](실험설계_10주차.md) 2장·5장·7장, [이슈 #6](https://github.com/travel-recommender/gachilo/issues/6), [#67](https://github.com/travel-recommender/gachilo/pull/67)(실험 중 P3 추천 카드 끄기, 병합됨).

## 켜는 방법

웹을 띄울 때 `NEXT_PUBLIC_EXPERIMENT_MODE=1`을 붙이면 그 웹에서 열리는 **모든 방이 실험 방**이다.
그룹마다 따로 띄우는 실험용 서버([week11_experiment_support.md](week11_experiment_support.md))에 붙여 쓰므로, 방마다 표시를 달지 않고 실행 설정 하나로 구분한다.
새로고침·재접속·뒤로 가기를 해도 실험 모드는 그대로 유지된다. 이 값을 빼고 띄우면 평소 서비스·시연 화면이다.

```sh
cd web
NEXT_PUBLIC_EXPERIMENT_MODE=1 NEXT_PUBLIC_API_BASE_URL=http://localhost:8111 \
NEXT_PUBLIC_DATASET=osaka_review_150 NEXT_PUBLIC_BASE_PATH='' \
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY='' NEXT_TELEMETRY_DISABLED=1 npm run dev -- --port 3111
```

## 실험 모드에서 달라지는 것

| 화면 | 평소 | 실험 모드 |
| --- | --- | --- |
| P3 장소 찾기 | 담으면 "함께 담은 곳" 추천 카드 | 카드를 **그리지 않는다** → 추천 API도 부르지 않는다 (2.1) |
| 대기 화면 | "방장이 하나를 고르는 중" | 방장·확정 이야기 없이 "일정 3개가 나왔어요…" |
| P7 후보 | 평균·최소 불만·공정성 + 방법 설명 | **일정 A·B·C**만. 사람마다 순서가 다르다. 서버 후보가 나오기 전 미리보기는 보여주지 않는다 |
| P7 설명 | 서버 요약 문장 | 배정된 일정에만 설명 문장 (아래). 날씨 안내 박스는 두 조건 모두 뺀다 |
| P8 일정 | 제목에 전략 이름, 방장 확정 버튼 | 제목 "일정 A", 주소는 `?c=A`(전략 이름 없음), **확정 버튼 없음**("다른 일정 보기") |
| P8 장소 이유 | "추천" 표시 + 이유 문장 | 표시는 두 조건 같게 두고, 이유 문장은 설명 있음 일정에서만 |
| /compare, /server-check | 연구·점검 화면 | 닫는다 (전략 이름이 보이므로) |

## 배정 규칙 (`web/src/lib/experiment.ts`)

- **글자(A·B·C) ↔ 전략**: 방마다 무작위로 정하고, 같은 방 사람은 모두 같은 글자를 본다 (5.1).
- **표시 순서**: 사람마다 무작위로 섞는다. 같은 사람은 몇 번을 들어와도 같은 순서다.
- **설명 배정**: 참가자 순번으로 5.3 표를 따른다. 7번째 사람부터는 다시 1번 행을 쓴다.
  - **순번은 방 참여자 목록의 순서다.** 진행자는 방을 만들 때 참가자 이름을 **순번대로** 넣는다(첫 이름 = 방장 = 1번).
- 응답 저장(조은)은 `assignment(roomId, memberId, memberIds)`로 각 일정의 글자·전략·표시 순서·설명 여부를 받아 함께 남기면 된다.

## 설명 문장

서버 요약은 첫 문장이 "○○ 전략의 시연용 후보입니다"라서 실험 화면에 쓰면 전략이 드러난다.
그래서 실험설계 5.4의 문장 틀을 엔진 결과와 내 입력으로 채운다(`web/src/lib/experiment.ts`). 문장을 만드는 데 AI는 쓰지 않는다.
설명 있음 조건에서만 보이고, 순서는 **모두에게 같은 설명 → 나에게만 보이는 설명**이다.

**모두에게 같은 설명** (`groupExplanation`) — 실제 장소 결과의 `planning`이 있을 때. 다른 사람의 입력은 드러내지 않고 숫자는 장소 수만 쓴다.
- 모두의 1순위 꼭 가기가 모두 들어갔어요 / 1순위 꼭 가기 중 일부는 이번 일정에 들어가지 못했어요. (`must_satisfied`)
  - 엔진은 1순위가 하나도 없어도 `must_satisfied = true`를 준다. 그래서 "모두 들어갔어요"는 **이 사람에게 1순위가 있을 때만** 쓴다. 화면은 꼭 가기의 첫 곳을 1순위로 보내고, 실험에서는 모두 꼭 가기 5곳을 고르므로 그룹 모두에게 같은 문장이 된다. "일부는 못 들어갔어요"는 1순위가 있었다는 뜻이라 늘 쓴다.
- 누군가 제외한 곳은 넣지 않았어요. (실제 장소 경로는 제외한 곳을 후보에서 뺀다. 결과 계산 뒤 내 입력이 바뀌어 내가 제외한 곳이 들어 있으면 이 문장은 빼고 "내가 제외한 곳 중 일부가 들어 있어요"만 쓴다)
- 하루 걸음 수는 그룹에서 가장 적은 걸음 한도를 넘지 않아요. (하루마다 가장 적은 한도로 검사한다. 한도 수치는 쓰지 않는다)
- 꼭 가기로 고른 곳 중 N곳은 넣지 못했어요. 주된 이유: 하루 활동 시간 초과, 여행 날짜에 모두 휴무. (`unplaced_count`, `exclusion_reason_counts` — 여러 날짜에 공통인 이유만, `reason_aggregation`이 `common_across_dates`일 때만. 모르는 코드는 "그 밖의 운영 조건")
  - 이유별 곳 수는 쓰지 않는다. 한 곳에 이유가 여러 개면 코드마다 1씩 세므로 합이 N보다 커질 수 있다. 이유 이름만 많은 순서로 쓴다.
- 아무도 고르지 않은 곳은 넣은 주체를 나눠 쓴다. P8 표시(`badgeOf`)와 같은 기준이다. 이 문장은 데모 방에도 나온다.
  - `ai_added`("AI 추천"): 모두의 취향·예산에 맞아 AI가 골라 넣었어요.
  - `rule_added`("추천"): 모두의 취향·예산에 맞아 규칙에 따라 골라 넣었어요. 두 경우다 — AI가 꺼져 있거나 답이 검증을 통과하지 못해 같은 후보를 규칙 순서로 넣었을 때(`real_ai.mjs`), 그리고 AI가 켜져 있어도 AI가 고른 곳이 검사에서 떨어진 자리를 예비 후보(`ai.backup`)로 메웠을 때(`real_candidates.mjs`).
  - `meal_fill`("추천"): 빈 식사 시간을 채우려고 넣었어요.
  - 여러 종류가 있으면 "아무도 고르지 않은 곳 중 N곳은 …고, M곳은 …어요."로 잇는다.

**나에게만 보이는 설명**
- 내 꼭 가기 N곳 중 M곳이 들어갔어요.
- 내 1순위 ○○은(는) 들어갔어요 / 들어가지 못했어요.
- 내가 제외한 곳은 넣지 않았어요. (그룹 문장이 이미 있으면 반복하지 않는다)
- 하루 예산의 X%, 걸음 한도의 Y%를 써요.

테스트는 어떤 문장에도 전략 이름이 들어가지 않는지, 그룹 문장에 숫자 뒤 원·보·%가 붙는 개인 조건 수치가 없는지 함께 검사한다.

## 정해진 것

- 가상 여행 날짜는 **11월 안**(현재 데이터의 검증 범위 2026-11-30까지)으로 잡는다. 정확한 날짜는 `audit` 결과를 보고 고른다.
- 실험용 서버는 조은이 정한 서버를 쓴다. 예비 실험은 Mac에서 돌린다.

## 남은 것

- 설문 화면(4장 S·Q·P 문항)과 응답 저장 연동 — 필드·API는 조은의 응답 저장 계약이 정해진 뒤 맞춘다.
- 설명 열람 여부 기록 — 응답 저장과 함께 붙인다.
- 실험 서버 묶음은 이 화면이 main에 들어간 뒤의 커밋으로 새로 준비한다.
