# 10주차: 짐·강수확률·지붕 보행로

Issue #5 조은 담당 구현. **PR #57의 225곳 통합 브랜치 위에 작성했으며 #57 병합 후 main으로 통합한다.** 서버에서 계산한 단일/세 후보에 적용한다. 브라우저의 서버 미연결 로컬 미리보기는 기존 계산을 유지한다. 기존 방/멤버 입력 및 후보 응답 스키마는 바꾸지 않는다. 각 후보의 `summary`에 예보 날짜·확률·조회시각, 지붕 근거 거리, 미확인 거리와 상대 짐 부담을 기록해 저장된 공동 결과로 공유한다.

## 짐

- 기존 `bag_load` 0/1/2 → 엔진 `bagLoad` 0/0.5/1을 유지한다. **상대 구매 부담이며 kg 측정값이 아니다.**
- 구간 상대 비용 = 도보 km × (1 + 0.35 × 그 구간 이전 누적 짐 점수). 구매는 방문 완료 후 누적하며 날짜가 바뀌면 초기화한다. 대중교통 구간은 기존 0.7km 접근 도보 추정만 운반 부담에 포함한다. 실제 요금·걸음수·이동시간을 임의로 늘리지 않는다.
- 다음 방문 선택 시 현재 짐의 운반 부담과 새 구매 후 남은 장소까지의 평균 도보 부담을 비교한다. 기존 `(1-load)` 항이 음수가 되어 쇼핑을 보상하던 문제를 제거했다.
- 같은 날 같은 방문지 집합을 유지하는 두 순서를 비교해, 짐을 고려한 결과의 여행 전체 상대 비용이 더 크면 원래 순서를 사용한다. 전역 최적해, 실제 피로 감소 또는 모든 여행에 대한 개선 보장은 아니다. 0.35는 예비 실험용 계수로 윤진의 실험 설계에서 보정할 수 있다.
- 영업시간·식사 시각·방문일·꼭 가기/제외·예산·걸음·활동시간 검사는 그대로 적용한다. 짐 선호가 이를 우회하지 않는다.

## 무료 예보

`backend/weather.py`가 서버 계산 직전에 오사카 고정 좌표(34.6937,135.5023)의 Open-Meteo 일별 `precipitation_probability_max`를 조회한다. 멤버 입력이나 선택 장소를 외부 예보 서비스로 전송하지 않는다.

- 일본 시간대, 오늘부터 16일 이내만 사용. % 단위를 검증해 0–1로 변환한다. **0%, null, 기간 밖, 연결 실패를 구분**한다.
- 일 최대 강수확률을 하루 전체의 보수적인 선호로 사용하며, 일정 시간대 강수량/강도나 현재 비가 온다는 의미는 아니다.
- TLS 검증, 3초 제한, 응답 256KiB 제한. 정상 캐시 30분, 실패 캐시 1분. 일본 날짜가 바뀌면 재조회하며 만료된 예보를 최신으로 표시하지 않는다.
- 실패·미확인 날짜는 날씨 가중치 없이 계산한다. `WEATHER_ENABLED=0`으로 외부 예보 조회를 끌 수 있다.
- 동일 입력 revision의 저장 결과는 멤버 전원에게 동일하게 유지한다. 새 예보가 기존 확정 결과를 자동 변경하지 않는다. 새 예보로 재계산하려면 입력을 재제출해 revision을 바꾼다.
- macOS Python 배포판에 기본 CA가 없으면 `/etc/ssl/cert.pem`을 사용한다. 명시적 `SSL_CERT_FILE` 설정은 보존한다. TLS 검증을 끄지 않는다.

```sh
python3 scripts/get_weather.py --start 2026-10-30 --end 2026-10-31
# 실제 시험일 기준 오늘~15일 뒤로 바꾼다. 기간 밖에는 예보가 없다고 표시한다.
export OSRM_FOOT_URL=http://localhost:5001
cd backend
python3 server.py
```

[Open-Meteo 문서](https://open-meteo.com/en/docs)의 무료 비상업 API를 사용한다. 날짜/확률/수집시각은 결과 설명에 함께 남긴다.

## 실제 지붕 데이터와 OSRM

`data/sheltered_paths.json`은 현재 자체 OSRM을 만들 때 사용한 `osaka-service.osm.pbf`에서 추출한 **742개 OSM 보행 way**다. 원본은 Geofabrik Kansai, 지도 스냅샷은 **2026-10-12 20:21:35 UTC**이며 10/30에 태그를 추출했다. 수집일을 최신 지도 확인일로 바꾸지 않는다. PBF SHA256·OSM way/node ID·형상·원본 태그·출처 링크·ODbL 출처 표시를 보존한다.

- `highway=footway/pedestrian/path` + `covered=yes/arcade/colonnade`만 사용한다. 접근 제한, 조건부 통행, 영업시간/공사 태그가 있는 way는 제외한다. 좌표 범위는 위도34.5–34.9/경도135.3–135.7 안의 원본에 있는 구간이다.
- **장소의 실내/야외 값으로 길의 지붕을 추정하지 않는다.** OSRM Route의 `annotations=nodes,distance`에서 인접 노드 쌍이 데이터와 정확히 일치하는 부분만 지붕 근거 거리로 계산한다. 나머지는 '미확인'이며 실제 야외 확정이라고 표시하지 않는다.
- 기본 Table 경로에 더해, 보행 1.2km 이하인 쌍 중 지붕 way 중간점을 경유할 수 있는 최대16개 방향별 쌍을 비교한다. 후보 중간점은 직선 합이 기본 경로의1.3배 이내인 가장 가까운 점이다. 쌍마다 기본/경유 Route를 각각 조회해 최대32회, 동시4회, 전체2.5초로 제한한다. 지붕 경로 전체를 탐색하는 최적화가 아니다.
- 비교 비용 = 경로 km + 강수확률 × **지붕 근거가 없는 km**. 비용이 낮고 지붕 거리도 늘어나는 경유 경로만 선택한다. 1.2km 이하·기본 대비35% 이내·추가5분 이내 조건을 모두 지킨다.
- 선택된 경로의 실제 OSRM 거리/시간을 일정 도착시각·걸음수·한도 검사에 사용한다. 표본 조회 밖, roof 데이터/Route 실패, 노드가 맞지 않는 경우는 기본 Table 경로를 유지한다. OSRM 전체 실패 시 기존 직선거리×1.35와 대중교통 추정으로 돌아간다.
- 스냅 거리는 모든 끝점/경유점에서100m 이내만 허용한다. OSRM은 반드시 자체 **foot.lua** 데이터여야 한다. URL의 `foot` 글자만으로 도보 프로필이 보장되지 않는다.
- 이 PR은 경로 선택·거리·시각·설명에 반영한다. **웹 지도에 지붕 경로선을 그리거나 길 안내를 제공하는 변경은 포함하지 않는다.**

지도 태그는 현장 조사·현재 개방·안전·휠체어 접근성 보증이 아니다. 아케이드 밖까지 비를 피할 수 있다고 주장하지 않는다. 미확인 보행 구간과 대중교통 접근 도보는 보수적으로 노출 비용 후보로 남긴다. 지붕 증거가 없는 쌍은 기본 경로를 유지한다.

데이터 재생성 (서비스 실행에 pyosmium은 필요 없음):

```sh
# 별도 가상환경에 osmium을 설치하고, OSRM을 만든 동일 PBF를 사용한다.
python3 scripts/prepare_sheltered_paths.py --pbf /path/to/osaka-service.osm.pbf \
  --osm-timestamp 2026-10-12T20:21:35Z --output data/sheltered_paths.json
```

추출본에서 타임스탬프가 빠졌으므로 위 값은 원본 Kansai PBF 헤더에서 확인했다. 원본 Geofabrik 다운로드 출처: https://download.geofabrik.de/asia/japan/kansai.html . `© OpenStreetMap contributors`, [ODbL](https://www.openstreetmap.org/copyright). [covered 태그](https://wiki.openstreetmap.org/wiki/Key:covered), [OSRM Route 문서](https://project-osrm.org/docs/v5.24.0/api/).
