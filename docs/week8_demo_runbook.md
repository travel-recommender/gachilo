# 8주차 시연 실행·연결 복구 안내

확인일: 2026-10-23. 이 PR은 **main에 네트워크 오류 처리·실행기·안내서만 추가**한다. #47(화면), #52(서버), #53(엔진)의 코드는 포함하지 않는다. 현재 main에서 실행기의 기본값은 **데모 36곳**이다.

아래 150곳 브라우저·OSRM 검증 근거는 별도 로컬 통합본(main `d19a269` + #47 `def32f4` + #52 `70cea33` + #53 `3246f5a`, 수정 `bd174c6`)에서 얻었다. 이 PR만 병합해 150곳 서비스가 완성됐다고 해석하지 않는다. 기존 3046/3047 및 현재 3048 시연 서버는 업로드 작업으로 변경하지 않는다.

## 바로 실행하기

팀원: 이 PR 브랜치를 받은 저장소 폴더에서 시작한다. Node.js 24 이상·Python 3.10 이상이 필요하다. 처음에는 `web` 폴더에서 `npm ci`를 실행한다.

조은의 **현재 실행 중인 150곳 통합본**은 Finder → **바탕화면 → 활동 → gachilo → 8주차_시연**에 있다. 이 바로가기는 PR용 36곳 체크아웃과 별개이며, 업로드 때문에 이동하거나 교체하지 않았다.

1. 로컬 OSRM VM을 준비한 노트북은 **OSRM_시작.command** 더블클릭. 없으면 이 단계는 생략하고 추정 경로로 실행한다. 새 VM을 자동 생성하지 않는다. 조은 환경에서는 기존 도보 서버를 켜는 데 수십 초 걸릴 수 있다.
2. **시연_시작.command** 더블클릭. API와 미리 빌드한 웹을 실행하고 크롬을 연다.
3. **http://localhost:3048/** 접속. 주소의 localhost를 그대로 사용한다.
4. 끝나면 **시연_종료.command** 실행. 방·입력·확정 결과는 지우지 않는다. OSRM VM까지 끄려면 아래 stop 명령을 실행한다.

이미 실행 중이면 중복 서버를 만들지 않는다. 포트에 다른 프로그램이 있으면 자동 종료하지 않고 안내한다. 최초 빌드와 패키지 설치는 인터넷이 될 때 미리 끝내야 한다. 지금 이 노트북에는 빌드·패키지가 준비돼 있다.

터미널에서 같은 작업을 하려면:

```sh
cd /path/to/gachilo  # 이 PR을 받은 저장소 폴더
python3 scripts/demo_osrm.py start
python3 scripts/demo_server.py start
python3 scripts/demo_server.py status
```

종료:

```sh
python3 scripts/demo_server.py stop
python3 scripts/demo_osrm.py stop
```

코드를 바꾼 뒤에는 `stop` 후 `start --rebuild`를 실행한다. 주소·데이터 모드가 바뀌면 실행기가 기존 빌드 설정과 비교해 다시 빌드한다. #47/#52/#53이 통합된 코드에서 실제 장소 모드로 바꾸려면:

```sh
DEMO_DATASET=osaka_review_150 python3 scripts/demo_server.py start --rebuild
```

다음 실행에도 같은 `DEMO_DATASET`을 지정한다. main에 해당 변경들이 없는 동안은 기본 36곳을 사용한다. 이 시연본은 개발 서버가 아닌 **정적 빌드**를 사용하므로 수정만으로 화면이 바뀌지 않는다.

## 시연 직전 확인

- 전원 연결, 잠자기 해제, 위 status 명령에서 API·web 정상 확인.
- 방 생성 → 날짜·이름 → 이름별 4자리 PIN 설정. 초대 링크를 미리 보관한다.
- 일반 창은 방장, 시크릿 창/다른 브라우저는 동행자로 입력한다. 같은 탭에서 이름을 바꿔가며 시험하지 않는다.
- 각자 장소·예산·걸음 수 입력 → 제출 수 증가 → 후보 3개 → 방장 확정 → 모두 같은 일정 조회.
- 시험용으로만 쓰는 이름/PIN을 사용한다. 기존 사용자 DB를 삭제해서 초기화하지 않는다. 새 방을 만든다.
- 후보 요약의 **OSRM 도보 N구간**을 확인한다. 이미 계산한 후보는 저장된 결과이므로 OSRM을 켰다고 자동으로 다시 계산되지 않는다. 입력을 다시 제출하거나 새 방에서 계산한다.
- 별도 150곳 통합본에서는 장소가 검토용 150곳 목록이다. 선택한 장소 중 방문일 조건을 통과한 장소만 배치되며, 모든 장소가 일정 투입 확정 상태라는 뜻은 아니다. 일정이 비거나 필수 장소가 빠졌다는 안내는 발표 전에 확인한다.
- 환율은 **2026-09-30의 1엔=8.6253원**을 고정한 시험값이다. 오늘 환율이나 환전 견적으로 설명하지 않는다.
- 이번 환경은 유료 AI 호출을 사용하지 않는다. 구글 지도 키는 복사하지 않았으므로 외부 지도/숙소 검색을 포함한 시험은 별도다. 내부 장소 검색과 공동 결과·일정 목록은 사용할 수 있다.

## 다른 노트북·3대 기기 시연

현재 실행기는 **이 노트북의 localhost 전용**이다. 다른 기기에서 localhost:3048을 열면 조은 노트북에 연결되지 않는다. 오늘 검사는 실제 기기3대 시험을 대신하지 않는다.

팀 시연에서는 같은 네트워크의 서버 노트북 IP를 한 개 정하고, 다음 세 항목을 함께 맞춰 별도로 실행해야 한다.

1. API: `--host 0.0.0.0 --origin http://서버IP:3048`.
2. 웹 빌드: `NEXT_PUBLIC_API_BASE_URL=http://서버IP:8048`, `NEXT_PUBLIC_DATASET=osaka_review_150`, 빈 base path로 빌드.
3. 웹 정적 서버: `--bind 0.0.0.0 --directory web/out`로3048포트에서 제공. 모든 기기는 `http://서버IP:3048`로 접속.

IP/API주소를 바꿨으면 반드시 웹을 다시 빌드한다. 해당 설정은 팀과 정한 로컬 시연 네트워크에서만 사용한다. 공용 인터넷 배포용 인증·보안 설정은 별도다.

**팀 완료 확인:** 실제 기기3대에서 각자 입력 → 같은 결과를 두 차례 리허설. 한 기기를 네트워크에서 잠시 분리했다가 복귀시키고, 중복 제출·오래된 결과·확정 상태를 확인한다. 이 항목은 아직 완료 체크하지 않았다.

- API 프로세스 재시작 전후: 선택한 전략·revision·selectionVersion·결과 JSON 전체 동일. `week8_persistence_evidence.json`.
- 별도 150곳 통합본의 실제 OSRM 컨테이너: 정상 → 중지 → 재시작, 세 전략 모두 실제 경로 → 추정 경로 → 실제 경로 복구. `week8_osrm_recovery_evidence.json`.
- 일반 연결 실패, 실제 TCP 무응답, 응답 본문 중단, 사용자 취소, 재시도 자동 검사 통과.
- 별도 150곳 통합본: 백엔드73개·프런트엔드87개 검사, TypeScript 및 production build 성공.
- **이 PR의 main 기준 코드**: 백엔드65개·프런트엔드84개 검사, production build(타입 검사 포함) 성공. 별도3050/8050포트에서 36곳 세 후보 → 방장 확정 → API프로세스 재시작 → 동일 결과 복구를 확인했다. 검사 서버는 종료했고 기존3048 시연본은 유지했다.

원격 PR 병합, 실제 기기3대 리허설2회, 구글 지도 유료 API 동작까지 완료했다고 표시하지 않는다.
