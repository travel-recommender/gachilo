# 휴대폰 실험 서버·그룹 QR·응답 저장

PR #68의 H4 화면과 `docs/실험설계_10주차.md` 문항을 연결한다. 팀 1회와 조은·혜인·윤진 친구 각 1회, 그룹마다 **참가자 3명**. 팀 예비 점검을 친구 실험 결과와 합쳐 분석하지 않는다. 가상 오사카 여행일은 **2026-11-16~19 (4일)**이며 실제 실험일이 아니다.

## 이번에 제공하는 것

- 본인 토큰으로만 읽고 쓰는 사전 S1~S4, 일정 Q1~Q8(설명 조건이면 Q9 추가), 마지막 P1~P5 응답 API/화면.
- 서버가 PR #68과 **같은 assignment 함수**로 글자·전략·순서·설명 조건을 계산하여 기록한다. 참가자가 전략/점수/설명 조건을 제출하지 않는다.
- 참가자×일정별 입력 revision, 후보 해시, 실제 일정/본인 입력 스냅샷, 계산식에 의한 점수/반영률/예산·걸음 비율, 그룹 평균·최저·차이를 저장한다. 자동 점수는 사용자 설문 답과 구분한다.
- 화면 표시 기록은 **해당 화면이 visible 상태로 표시됐다는 이벤트**다. 설명을 실제로 읽고 이해했다는 증거가 아니다.
- 일정 변경 시 예전 평가를 보관하되 새 일정 평가에 섞지 않는다. 동일 응답 재전송은 중복 저장하지 않고 저장 후 답 변경은 409로 막는다. 변경 요청은 진행자에게 전달한다.
- P3 6곳 이상, 꼭 가기 5곳을 안내·화면 검사한다. 기존 `picks` 5 + `must` 첫 1 구조를 유지한다.
- 실험 서버에서는 방장 확정과 참가자 추가를 막는다. 기존 일반 서비스에는 영향을 주지 않는다.
- 그룹별 DB·QR, 실행 버전·데이터 해시 고정, SQLite 백업/복원, 로컬 CSV/JSON 내보내기.

## 혜인·윤진 진행자 준비 (Mac/Linux; Windows는 WSL)

참가자는 iPhone/Android 브라우저만 있으면 된다. 아래 설치·실행은 **서버 노트북 1대**에서 한다. WSL은 별도로 LAN 접근/방화벽 구성이 필요하므로 그대로 휴대폰 접속된다고 가정하지 않는다. Mac에서 검증한 후 각 운영 노트북과 실제 폰으로 시작 전 확인한다.

1. 이 브랜치를 받아 Node 24 이상, Python 3.10 이상을 준비한다. 작업 중 파일이 있는 기존 폴더의 브랜치를 강제로 바꾸지 않는다.
2. 저장소 루트에서 `python3 -m venv .venv` → `source .venv/bin/activate` → `python -m pip install -r scripts/requirements-experiment.txt`. `cd web && npm ci && cd ..`로 웹 의존성을 준비한다.
3. 코드 변경이 없는 커밋에서 `python scripts/experiment_lan.py build` 실행. 이 명령이 실험 모드와 `/backend` 주소를 고정해 웹을 빌드한다. 코드가 바뀌면 새 빌드·새 bundle을 만든다.
4. 노트북과 휴대폰을 같은 Wi-Fi에 연결한다. Mac은 `ipconfig getifaddr en0`로 주소를 확인한다. 다른 인터페이스를 쓰면 시스템 설정의 Wi-Fi TCP/IP 주소를 확인한다. 학교/공공 Wi-Fi의 기기 간 차단 기능이 있으면 같은 이름의 Wi-Fi라도 연결되지 않을 수 있다.
5. 우선 아래 모의 점검으로 방 입장·후보·설문 저장·재접속을 검사한다. 값은 실제 참가자 데이터와 분리된다.

```sh
python scripts/experiment_lan.py start --host 192.168.0.10 --group hyein --mode rehearsal
```

`192.168.0.10`은 예시다. 현재 서버 노트북 주소로 바꾼다. 그룹은 `team`, `joeun`, `hyein`, `yunjin`, 한 노트북에서 4개를 준비하려면 `all`이다. 웹 포트는 각각 3140/3141/3142/3143, API는 8140/8141/8142/8143으로 loopback에만 열린다.

## 실제 실험 시작

**모의 점검 완료만으로 실제 실험 시작 준비가 끝났다고 표시하지 않는다.** 다음 조건을 진행자가 확인한다.

- 혜인·윤진의 동의 절차 및 설명 문장 내용 확인. #68의 개인별 설명은 연결되어 있지만 설계 5.4의 공통 설명·빠진 이유는 윤진 담당 후속이므로, 실제 사용할 설명 범위를 팀이 확인한다.
- 실시간 조회: 서버 환경변수 `GOOGLE_PLACES_API_KEY` 설정. 이 키가 없으면 기존 main은 실제 장소 후보 계산을 멈추므로 launcher도 live 시작을 거절한다. **키 값은 Git·QR·채팅에 넣지 않는다.** `LIVE_CHECK_MOCK`/`AI_MOCK`은 live에서 금지한다.
- 솜솜AI를 사용할 실험이면 `SOMSOM_API_KEY`를 모든 그룹에서 동일하게 준비한다. 키가 없는 규칙 설명/일정과 AI 조건을 한 실험에 혼합하지 않는다. OSRM도 사용할 경우 `OSRM_FOOT_URL`을 공통으로 설정하고 정상/실패 대체 상태를 확인한다.
- 지도/숙소 검색은 별도의 웹 지도 키가 필요하다. 필요한 경우 `web/.env.local`에 공개 웹 키를 설정한 후 **다시 build**한다. 파일은 커밋하지 않는다. 브라우저 키는 localhost와 실제 LAN origin을 허용하도록 설정되어야 한다.
- 환율은 2026-09-30 하나은행 **8.6253원/엔** 고정 실험값이며 현재 환율이 아니다. 모든 그룹 같은 값으로 비교한다.
- 외부 API 호출은 비용이 발생할 수 있다. 이번 자동 QA는 외부 호출을 사용하지 않는다. 실제 키 연결/실기기 점검은 운영자가 별도로 수행한다.

환경변수를 준비한 뒤 실행:

```sh
python scripts/experiment_lan.py start --host 192.168.0.10 --group hyein --mode live
```

기본 기록 위치 `.local/experiment-live/`는 `.local/experiment-rehearsal/`과 분리된다. 새로운 실험을 다시 하려면 `--bundle .local/experiment-live-session2`처럼 새 경로를 쓴다. 같은 경로로 재실행하면 기존 방·PIN·응답을 복원한다. 실행 중 원본 데이터/코드를 고치지 않는다.

## QR과 번호 배정

- 실행 후 출력되는 `qr-share/QR_접속안내.html`을 열면 QR 4종(선택한 그룹만)과 접속 주소가 나온다. QR은 그룹 안내 주소만 담고 방장/참가자 토큰·PIN을 담지 않는다.
- 진행자가 참가자 1·2·3을 각각 지정한다. **진행자용 네 번째 자리는 없다.** 팀 실험은 세 팀원이 각각 번호를 사용하고, 친구 실험은 친구 3명이 번호를 사용한다.
- 참가자 1은 사전에 만들어진 방장 자리다. 진행자가 해당 그룹 `groups/<그룹>/room-private.json`의 `participant1Pin`만 확인해 **1번 본인에게 따로** 전달한다. JSON 전체에는 접속 토큰이 있으므로 공유하지 않는다. 2·3번은 첫 입장 때 개인 PIN을 정한다.
- 혜인·윤진이 자기 노트북/다른 장소에서 진행하면 그 노트북에서 실행하고 새 QR을 전달한다. 조은 Mac용 QR을 그대로 보내면 안 된다. Wi-Fi 주소가 바뀌면 재실행해 QR을 다시 만든다.

## 참가자에게 함께 보낼 안내

> 노트북과 같은 Wi-Fi에 연결하고, 본인 그룹 QR을 Safari 또는 Chrome으로 열어 주세요. 진행자가 준 참가자 번호를 선택하고 PIN을 기억해 주세요. 1번은 받은 PIN으로 다시 입장하고, 2·3번은 PIN을 직접 정합니다.
>
> 가상 여행은 11월 16~19일 오사카 4일 여행입니다. 안내·동의 후 사전 설문 → 가고 싶은 곳 6곳 이상 → 꼭 가기 5곳(먼저 고른 곳이 1순위) → 예산·체력 입력을 진행해 주세요.
>
> 모두 입력하면 일정 A·B·C가 나옵니다. 각 일정을 살펴보고 ‘이 일정 평가하기’로 점수를 입력한 뒤 마지막 설문까지 저장해 주세요. 다른 사람과 상의하지 않고 답하며, 일정을 확정하지 않습니다.
>
> ‘모든 응답이 저장됐어요’ 화면을 진행자에게 보여 주세요. 탭을 닫거나 다른 브라우저로 바꾸면 QR과 본인 번호·PIN으로 다시 들어옵니다. 연결이 끊기면 새 번호를 만들지 말고 진행자에게 알려 주세요.

## 저장 계약·내보내기

`GET/PUT /rooms/{roomId}/experiment/{memberId}`, `Authorization: Bearer 본인 submissionToken`.
PUT 종류: `pre`, `view`, `candidate`, `post`. pre 외에는 `revision`과 `candidateHash`가 필요하다. GET은 본인의 응답·진행 상태만 돌려주고 전략/자동점수/다른 참가자 응답을 공개하지 않는다. 이 API는 `EXPERIMENT_SERVER=1`에서만 열린다.

```sh
python scripts/experiment_export.py --bundle .local/experiment-live --group hyein --out .local/exports/hyein-01
python scripts/experiment_support.py --bundle .local/experiment-live backup --group hyein --output .local/backups/hyein-01
```

실행기·DB가 정상인 상태에서 백업한다. export에는 토큰·PIN·참가자 이름이 없다. `responses.csv`는 참가자×일정 한 줄, `evidence.json`은 입력/후보 근거다. 모의 여부와 revision을 확인하고 예전 revision을 현재 응답에 합산하지 않는다. JSON·CSV·SQLite는 `.local/`에 두고 Git에 올리지 않는다. 문항 자유응답은 개인정보를 적지 않도록 안내한다.

복원은 기존 `experiment_support.py restore --help`에 따라 새 그룹 경로로 한다. 복원 후 방 입장 정보와 설문 개수도 점검한다. 단순한 JSON 내보내기는 재접속 복원용 백업이 아니다.

## 확인 범위

자동 검사는 외부 API 모의 응답과 별도 테스트 DB로 수행한다. 실제 폰 세 대 전체 입력·공통 설명 최종안·실제 키 연결·동의 절차를 팀원이 마친 후 최종 예비 점검을 완료 처리한다.
