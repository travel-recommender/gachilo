# AI 환각 방지 — 6주차

> 이슈 #2 「환각 방지(윤진)」 산출물
> 코드: `backend/engine/ai.ts` · 검사: `ai_check.mjs` `ai_fallback_check.mjs` `ai_repeat_check.mjs`

## 1. 접근 — 검사보다 구조

처음에는 모델이 자유 문장을 쓰고 그 문장을 사후에 검사하는 방식이었다. 5주차 리뷰에서
두 가지가 그대로 통과했다.

- `"교토타워를 방문해요."` — 카탈로그에 없는 장소라 이름 대조에 걸리지 않음
- `"모든 장소의 입장료는 0원이에요."` — `0`이 입력 어딘가에 있어서 숫자 검사를 통과

문장을 검사해서는 다 막을 수 없다고 판단해, **모델이 글자를 쓰지 않게** 구조를 바꿨다.

| | 전 | 후 |
| --- | --- | --- |
| 모델 출력 | 자유 문장 | 코드 선택 |
| 장소 이름 | 모델이 씀 | 코드가 근거에서 꺼냄 |
| 숫자 | 모델이 씀 | 코드가 근거에서 꺼냄 |
| 검증 | 문장 분석 | 코드 대조 |

```json
{ "ai_added": [{ "id": "shinsekai", "reason_code": "no_one_dislikes" }],
  "summary": ["must_kept", "ai_filled", "options_free"] }
```

모델이 하는 일은 두 가지다. 후보 중에서 장소를 고르는 것, 이번 결과에 해당하는 설명을
고르는 것. 문장은 코드가 템플릿으로 만든다.

## 2. "주어진 숫자 외 지어내지 말 것"

세 겹으로 막는다.

1. **구조** — 모델 출력에 숫자를 쓸 자리가 없다. 스키마가 id와 코드만 받는다.
2. **프롬프트** — "입력에 주어진 것 외의 장소·숫자·사실을 만들어 내지 마십시오."
3. **검증** — 정의되지 않은 코드는 전부 거부. 숫자가 섞인 문자열은 "알 수 없는 설명 코드"로 걸린다.

설명 코드는 근거가 있을 때만 쓸 수 있다. 코드가 맞아도 이번 결과에 해당하지 않으면 거부한다.

| 코드 | 쓸 수 있는 조건 |
| --- | --- |
| `must_kept` | '꼭 가고 싶은 곳'이 실제로 있을 때 |
| `ai_filled` | AI가 실제로 장소를 추가했을 때 |
| `no_room` | 추가할 자리가 없거나 추가하지 않았을 때 |
| `budget_limited` | 남은 예산이 0보다 클 때 |
| `options_free` | 옵션 장소가 실제로 있을 때 |
| `veto_excluded` | 거부된 곳이 실제로 있을 때 |

## 3. AI가 추가한 장소의 근거

### 입력 쪽

모델은 `ai_candidates` 안에서만 고를 수 있고, 각 후보에는 판단 근거가 함께 들어간다.

| 필드 | 뜻 |
| --- | --- |
| `fit_min` | 가장 안 맞는 사람의 적합도 (0~1) |
| `fit_avg` | 평균 적합도 |
| `taste_match` | 이 카테고리를 고른 적 있는 인원 수 |
| `cost_won` · `stay_min` · `open` · `area` | 제약 검사용 사실값 |

후보는 코드가 미리 거른다. 아무도 안 골랐고, 거부되지 않았고, 남은 예산 안이고,
최저 적합도 0.2 이상인 곳만. 카테고리별로 돌아가며 뽑아 한 종류로 쏠리지 않게 한다.

### 출력 쪽

AI가 장소를 추가하면, 그 판단에 쓰인 입력값을 그대로 결과에 남긴다. 나중에
"왜 이 장소가 들어왔나"를 되짚을 수 있다.

```json
{ "used": true, "added": ["shinsekai"], "ms": 11,
  "basis": [{ "id": "shinsekai", "name": "신세카이 거리", "reason_code": "no_one_dislikes",
              "fit_min": 0.43, "fit_avg": 0.49, "taste_match": 3, "cost_won": 0 }] }
```

`AI_DEBUG=1` 로 서버 로그에 남는다.

## 4. 반복 테스트

```sh
SOMSOM_API_KEY=... node ai_repeat_check.mjs
SOMSOM_API_KEY=... RUNS=5 MODELS=gemini-3.5-flash-lite,claude-haiku-4-5-20251001 node ai_repeat_check.mjs
```

시나리오 2개(자리가 남는 경우 / 예산이 빠듯한 경우)를 모델마다 N회 돌린다.
입력은 고정이므로 회차 간 차이는 모델의 비결정성에서만 온다.

기록하는 것: 회차별 사실 오류 수, 소요 시간, 고른 장소, 고른 설명 코드,
회차 간 결과 일치 여부. 상세 로그는 `ai_runs_<날짜>.json` 으로 저장된다.

사실 오류가 한 건이라도 있으면 종료 코드 1로 실패 처리한다.

### 거부되어야 하는 출력 (`ai_check.mjs`)

```
거부함 · 없는 장소             — 후보 밖 장소: kyoto_tower
거부함 · 자유 문장(없는 장소)   — 알 수 없는 설명 코드
거부함 · 자유 문장(지어낸 가격) — 알 수 없는 설명 코드
거부함 · 근거 없는 설명         — 근거가 없는 설명 (ai_filled)
거부함 · 지어낸 숫자           — 알 수 없는 설명 코드
거부함 · 모르는 이유 코드       — 알 수 없는 이유 코드
```

앞의 둘은 5주차 리뷰에서 실제로 통과했던 출력이다. 회귀 검사로 남겨 둔다.

## 5. 한계

- 모델이 **엉뚱하지만 형식은 맞는 선택**을 하는 것은 막지 못한다. 예산 안의 장소를
  고르되 어울리지 않는 곳을 고를 수 있다. 이건 사실 오류가 아니라 추천 품질 문제이고,
  반복 테스트의 일치 여부로 간접 확인한다.
- 설명 코드가 7개뿐이라 표현이 단조롭다. 코드를 늘리는 쪽은 안전하지만, 자유 문장으로
  되돌리는 것은 위 두 사례가 다시 생길 수 있어 권하지 않는다.
- 150곳 경로(`real.mjs`)에는 AI가 붙어 있지 않다. 그쪽으로 시연한다면 이 검증도
  그 경로에 다시 붙여야 한다.
