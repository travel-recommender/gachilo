## 실행

Node.js 24 이상. API 키·외부 요청·유료 호출 없이 실행한다.

```sh
node scripts/validate_real_schedule.mjs --report
node --test scripts/test_real_schedule.mjs
```

입력 파일로 한 날짜를 검사할 수도 있다. 날짜는 일본 현지 날짜이며 현재 검토 범위는 **2026-10-01~2026-11-30**이다. 범위 밖 날짜를 임의의 평일 시간표로 처리하지 않는다.

```json
{
  "date": "2026-10-01",
  "place_ids": ["osaka_009", "osaka_012", "osaka_015"],
  "krw_per_jpy": "9.2",
  "budget_krw": 50000,
  "step_limit": 15000,
  "active_min": 600
}
```

```sh
node scripts/validate_real_schedule.mjs --request input.json
```

입력 오류는 종료 코드 1, 배치·제약 검사 실패는 2를 반환한다. `--report`는 실패 장소까지 담는 진단 보고서이므로 전체 150곳의 실패를 종료 코드로 판단하지 않는다. `passed_model_checks`와 각 `violations`를 확인한다.

## 검증 범위와 결과

수집 ID·좌표·카테고리를 보존하고 비용만 원화로 한 번 환산한다. 소수점 환산은 정수 연산으로 ROUND_HALF_UP를 적용한다. **환율 9.2는 재현용 가정값**이며 실제 시세·팀 확정 환율이 아니다.

`buildSchedule`를 그대로 호출하되 `fillMeals:false`로 데모 36곳 자동 삽입을 막는다. `bag_load / 2`는 기존 엔진에 상대 점수를 연결하는 모델 변환안이다. 원본 짐 점수 0·1·2와 get_luggage_score 규칙은 보존하며 kg로 해석하지 않는다. 이 변환과 선택 수 우선 순서는 후속 PR의 팀 검토 범위다. 실내 여부를 이동 경로 아케이드 여부로 복사하지 않고, 인기도·날씨 노출값도 만들어 넣지 않는다. 후속 실제 모드는 여러 날짜에 대해 일일 검사를 반복하며, 행정구를 관광 권역이라고 가정하지 않는다. 최적 동선 탐색은 아니다.

원본 150곳을 검사해 구조화된 날짜 규칙 미비·비용 미확인·예약/휴무 등의 사유를 기록했다. 일정에 넣은 장소가 하나라도 빠지면 성공으로 처리하지 않는다. 휴무·공휴일 다음 날 휴관·특별 영업·최종입장·점심 가격 적용 시간·예산/걸음/활동시간 초과를 검사한다.

**한계:** 교통비·숙박·추가 식사·쇼핑 구매비를 포함한 여행 총예산 검사가 아니다. 직선거리×1.35와 기존 대중교통 추정식을 썼으며 실제 도보 경로·시간표를 확인한 것이 아니다. 걸음 수는 장소 간 이동만 포함하고 시설 내부와 숙소 왕복은 빠진다. 단독 공원 시나리오의 0보는 산책을 안 한다는 뜻이 아니다. 활동시간은 09시 이후 대기 포함이며 시설 대기열·날씨·임시 휴업은 보장하지 않는다.

## 실제 장소 연결 검증

`backend/README.md`의 실제 장소 여행방 절을 참고한다. 새 방에 `dataset=osaka_review_150`을 명시하고 `/api/places`의 ID를 사용한다. 실제 모드 결과는 `status=draft`, 세부 검증은 `planning.status`다. 조건 미충족·빈 결과도 성공한 일정으로 표시하지 않는다.

[전체 투입 실험 결과](../data/week5/real_catalog_integration_20260930.json)는 `node scripts/audit_real_catalog.mjs data/week5/real_catalog_integration_20260930.json`으로 재현한다. 가상 참여자 6명에게 실제 ID를 25곳씩 배분했고, 7일·일일 확인 비용 10만원·2만 걸음·720분 상한을 적용했다. 장소별 제외 이유와 배치된 시간·비용이 포함된다. 개인정보와 실제 환율은 사용하지 않았다.

검사 범위: 백엔드 28건, 날짜·일정·전체 투입 재현 검사 26건, 기존 데이터 검사 15건. Python 3.14·Node 24. 데이터 검사에는 requests가 필요하다. 기존 Chrome 화면 검증은 ‘테스트용 가상값’으로 별도 DB에서 수행했다. 이번에는 아래 실제 확인값을 로드한 HTTP 생성·입력·계산·조회도 별도 임시 DB로 통과했다(선택 3곳 보존, 1200 JPY→10,350 KRW, 저장 결과 일치). Windows·모바일 실기기와 외부 배포는 검증하지 않았다.
