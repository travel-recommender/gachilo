# 이슈 #3 10-b — 실제 장소 P7/P8 서버 연결

`dataset=osaka_review_150` 방에서 세 전략 요청이 400으로 거절되던 문제를 해결한다. 전원 제출 → 서버가 세 후보 계산 → 한 번에 SQLite 저장 → 방장이 확정 → 모든 참여자가 같은 결과를 조회한다. 요청·응답은 [공용 결과 API](week6_shared_results_api.md)와 같으며 #47의 화면이 보내는 실제 `place_id`를 사용한다.

## 계약과 실패 처리

- `POST /rooms/{id}/calculate`: 방장 토큰, `strategies=[average,least_misery,fairness]`, 현재 revision. 실제 방은 `real_candidates.mjs`, 데모 방은 기존 `candidates.mjs`를 호출한다.
- 세 후보가 모두 생성·검증돼야 저장한다. 실제 방에 데모 ID, 다른 날짜, 중복 장소, 잘못된 시각, 부분 묶음, 빈 후보가 나오면 저장하지 않는다. 실패 후 작업 잠금이 해제되어 재시도할 수 있다.
- 같은 revision의 계산은 실행 중 202, 완료 후 캐시 200이다. 재제출·새 참여자·늦은 작업의 덮어쓰기 방지, 방장만 확정, 선택 버전 충돌 409는 기존 규칙을 유지한다.
- `days[].items`에 `startMin/endMin`, `source/reason`, `aiAdded/filled`를 제공한다. 지표는 그 **최종 날짜별 일정**에서 계산하고, 빈 날짜를 포함한 여행 일수로 일평균을 구한다.
- 모든 후보가 여행 가능 판정을 뜻하지는 않는다. `ready`는 방장 확정 상태이며, 실제 후보의 `planning={status: draft, schedule_ready: false}`와 요약의 제한 사항을 함께 읽는다.
- 환율은 기존 하나은행 출처 설정 세 항목이 모두 필요하다. 누락 시 안내를 포함한 503. 유효한 장소가 하나도 배치되지 않으면 날짜·장소·한도를 다시 확인하도록 503을 반환한다. 빈 후보를 성공으로 저장하지 않는다.

## 실제 장소 계산 경계

1. 날짜별 운영·휴무·최종입장·예약·가격·좌표·체류 정책 검사를 통과한 **사용자 선택 장소만** 계산용 목록에 넣는다. 데모 36곳이나 새 수집 검토본 55곳으로 보충하지 않는다.
2. 기존 `buildConsensus`를 날짜·전략마다 호출한다. 기존 평균/최소불만/공정성 점수식을 복제하거나 변경하지 않는다. 실제 장소에 없는 popularity는 없는 상태로 두고 그 보너스 항만 0으로 처리한다. 선택·꼭 가기·카테고리 취향·예산 항은 기존 규칙을 사용한다.
3. 날짜별 남은 장소로 합의를 계산하므로 일일 예산을 넘겨 다른 날 예산에서 빌리지 않는다. 전원 동행 core만 전달하며 부분 동행은 추가하지 않는다. 각자의 1순위도 운영·예산·걷기·활동시간 검사를 우회하지 못한다. 미배치·꼭 가기 미충족·빈 날짜를 요약에 표시한다.
4. 현재 서버가 저장하는 tradeoffs의 pace(자리 수), spend(지출 상한), distance(거리 벌점)를 기존 함수로 연결한다. `validateDay/buildSchedule`의 기존 끼니 시각·영업시간 배치를 재사용한다. 시간표 검사를 통과한 항목만 응답에 남긴다.
5. 쇼핑 구매액은 비용 소계에서 제외한다. 계산 내부 합계의 0은 구매액 무료를 뜻하지 않으며 항목 근거와 전체 요약에 제외 범위를 명시한다. 입장권·대표 메뉴는 날짜별 금액과 설정 환율로 계산한다.
6. 세 전략은 한 OSRM 조회 결과를 재사용한다. 실패·미설정은 기존 추정식으로 돌아가고 최종 경로 출처를 요약한다. 숙소 왕복·시설 내부 걷기·교통 시간표는 포함하지 않는다.

## #47 및 윤진 담당 10-c와의 관계

#47의 `/api/places` 목록·P7/P8 실제 ID를 서버가 받아 처리하는 부분이 10-b다. 이 PR은 #47 화면 코드를 변경하지 않는다. #47과 합친 후 실제 브라우저/기기에서 입력 → 후보 → 확정 화면을 확인해야 한다.

10-c와 접하는 최소 연결 코드는 새 `real_candidates.mjs`에 모았다. 단일 평균 호환 경로 `real.mjs`는 유지한다. 윤진님은 기존 점수식에 실제 데이터가 전달되는 부분과 날짜별 배치 방식을 검토하면 된다. #51의 최소불만 알고리즘 변경은 이 PR에 미리 포함하지 않는다. 개인별 최소 만족 보장/전략 품질 시뮬레이션 결과는 별도 검증이다.

실제 데이터의 미선택 장소·끼니 자동 추가와 AI 설명은 아직 활성화하지 않는다. 따라서 `source=selected`, `aiAdded=false`, `filled=false`, `explanationSource=rules`다. 전략들이 독립 계산돼도 입력과 제약에 따라 같은 일정이 나올 수 있다. 150곳 전체 검증 완료, 새 55곳 승격, 브랜드·시설 중복 배치 정책, 자동 최신 환율, 3대 실기기 완료를 이 PR의 완료로 표시하지 않는다.

Node 24 이상, Python 3.10 이상. 외부 유료 호출 없이 실행한다.

```sh
cd backend
python3 -m unittest test_real_candidates test_candidates test_real_engine test_routing
cd ..
node --test backend/engine/real_candidates.test.mjs backend/engine/candidates.test.mjs
```

- 로컬 OSRM 대역 서버로 실제 Python→Node 경로에서 조회 1회와 세 후보 거리 반영 확인.
