# 지점 자동 배치 — 엔진·서버·화면 통합 상태

> 이슈 #6 「지점 자동 배치(실험 전 적용) — 추천 엔진(윤진)」. 데이터(브랜드·교체 그룹)는 조은 #73, 화면 표시는 혜인.
> 2026-11-12 결정: 이번 실험에도 적용한다. 참가자가 지점을 다시 고르는 화면은 없다.
>
> **PR #76에는 엔진·서버 계약과 화면 설명 연결이 함께 들어 있다.** 원래 #74의 엔진 문서였으나, 현재 브랜치에는 #71 설명 문장 및 #75 지점 표시 연결도 포함되어 있다. 아래는 이 통합 브랜치의 구현 상태이며, PR 병합이나 실제 참가자 실험 완료를 뜻하지 않는다.

## 1. 무엇을 하나

같은 가게의 지점이 여러 곳이면, 엔진이 일정을 다 만든 뒤 **마지막 단계에서** 지점을 바꿔 본다.

| 경우 | 하는 일 | `branch.reasonCode` |
| --- | --- | --- |
| 앞뒤 장소와 더 가까운 지점이 있다 | 그날 검사를 모두 통과하면서 이동 시간이 **1분 이상** 줄어드는 지점 중 가장 짧은 곳으로 바꾼다. 줄지 않거나 같으면 원래 지점을 유지한다 | `shorter_route` (+ `savedMin`) |
| 고른 지점이 그날 운영 조건에 맞지 않는다 (예: 551 본점 11/17 휴무) | 남은 날에 원래 지점이 영업하면 **원래 지점을 기다린다**(고른 지점이 우선). 남은 날에도 영업하지 않으면 그날 영업하는 같은 교체 그룹 지점을 대신 넣는다. 기다렸는데 결국 원래 지점이 그날 검사(예산·시간 등)에서 떨어지면, 그 전략을 한 번 더 짜서 휴무인 날 바로 대체하고, 고른 곳이 더 많이 반영되는 쪽을 쓴다. 이후 위의 이동 비교도 똑같이 적용한다 | `original_unavailable` |

- **다른 구성원이 같은 그룹의 다른 지점을 골랐으면** 그 지점도 이동 비교에 넣는다. 구성원이 고른 지점이 이동을 1분이라도 줄이면 아무도 고르지 않은 지점보다 먼저 쓰고, `branch` 표시 없이 그 사람의 선택으로 둔다.
- **같은 교체 그룹은 같은 곳이다.** 그룹의 어느 지점이든 한 번 들어가면, 그 그룹의 다른 지점(원래 고른 곳 포함)은 남은 날에도 다시 넣지 않는다. 두 사람이 같은 가게의 다른 지점을 골라도 한 번만 방문한다.
- 세 후보(A · B · C)에 **같은 규칙**을 쓴다. 전략이 고른 장소를 바꾸지 않고, 그 장소의 지점만 바꾼다.
- 바꾼 항목에만 `branch: {fromPlaceId, reasonCode, savedMin}`이 붙는다. `fromPlaceId`는 원래 고른 곳이다.
- 이동 시간은 서버의 경로 계산을 그대로 쓴다(OSRM이 켜져 있으면 OSRM, 꺼져 있으면 거리 추정). 그날의 장소 사이 이동 시간 합을 비교한다.

## 2. 바꿀 수 있는 지점

모든 조건을 만족해야 한다.

1. **같은 `branch_group_id`**. 같은 브랜드여도 방문 목적이 다르면(551 식당 ↔ 포장, ZARA ↔ ZARA MAN) 바꾸지 않는다. `null`은 묶지 않은 곳이라 바꾸지 않는다.
2. **그날 검사 통과**: 방문일 운영 조건, 실시간 영업 확인, 하루 예산·걸음·활동 시간, 영업·입장 마감 시간. 기존 일정 검사(`validateDay`)를 그대로 다시 돌린다. 폐업 보류 지점(이치란 도톤보리 본관)은 이 검사에서 빠진다.
3. **제외 존중**: 누군가 제외한 지점으로 바꾸지 않는다. 누군가 그 브랜드의 지점을 하나라도 제외했으면 그 브랜드는 바꾸지 않는다.
4. **중복 금지**: 여행 중 이미 들어간 지점으로는 바꾸지 않는다. 구성원이 직접 담은 같은 그룹 지점은 일반 교체 후보 3곳과 별도로 비교하고, 이동이 줄면 우선한다(1장). 같은 교체 그룹은 여행 전체에서 한 번만 방문한다.
5. **AI·규칙이 추가한 곳은 바꾸지 않는다.** 구성원이 고른 곳만 바꾼다. 구성원 장소와 같은 교체 그룹의 지점은 **상한과 상관없이 전부** AI·규칙 채우기 후보에서 뺀다. 같은 가게가 따로 한 번 더 들어가거나, 채우기로 들어간 지점 때문에 꼭 가기가 `branch` 표시 없이 반영으로 세어지는 일을 막는다.
6. **후보 수 상한**: 고른 곳마다 위 조건을 통과한 지점 중 **최대 3곳**(`BRANCH_CANDIDATE_LIMIT`)만 본다. 순서는 구성원이 담은 다른 장소(제외한 곳은 뺌) 중 가장 가까운 곳까지의 거리가 짧은 순이다(같이 갈 장소 근처의 지점을 남긴다). 날짜 배정 전에 정하므로 다른 날 갈 장소도 기준에 섞인다. 상위 3곳이 실시간 확인에서 모두 떨어지면 4번째로 넘어가지 않고 원래 지점을 유지한다. 실시간 확인(Google)과 경로 표, 일정 계산이 같은 함수(`branchCandidates`)를 써서 규칙이 어긋나지 않고 호출 수가 묶인다.

## 3. 같은 가게면 반영으로 센다

- 서버 `planning`: 같은 교체 그룹의 다른 지점이 들어갔으면 원래 고른 곳은 **반영**이다(`unplaced_count`, `must_satisfied`). 교체 없이 다른 사람이 고른 같은 그룹 지점이 들어간 경우도 반영이다.
- 설명 문장(`web/src/lib/experiment.ts`의 `placedEquivalentOf`): 실제 ID가 있으면 우선하고, 없으면 같은 `branch_group_id`의 배치를 찾아 "내 꼭 가기 N곳 중 M곳"과 "내 1순위"를 계산한다. 1순위가 다른 지점으로 들어갔으면 실제 지점 이름과 함께 "같은 가게의 다른 지점"이라고 설명한다. 교체 없이 다른 사람이 고른 같은 그룹 지점이 들어간 경우도 반영된다. 실험 결과 내보내기도 고정된 카탈로그의 교체 그룹으로 같은 기준을 적용한다.
- 기준은 교체 그룹(`branch_group_id`)이다. 교체 자체가 같은 그룹 안에서만 일어나므로, 반영으로 세는 것도 같은 그룹뿐이다.

## 4. 설명 문장 (설명 있음 조건에서만)

`web/src/lib/shared-flow.ts`의 `branchNoteOf`가 바뀐 항목마다 정해진 문장을 만든다. AI가 지점·숫자를 지어내지 않는다. 분은 해당 항목의 엔진 계산값 `savedMin`이다.

- 이동 단축: "같은 가게의 앞뒤 장소와 더 가까운 지점으로 바꿔 이동이 약 12분 줄었어요."
- 휴무 대체: "고른 지점이 그날 운영하지 않아 같은 가게의 영업하는 지점으로 넣었어요."

설명 없음 조건에서는 이유를 숨긴다. "지점 변경" 표시와 "고른 곳: 원래 지점 → 배치: 실제 지점" 문구는 두 조건에 똑같이 보인다. 개인 설명의 꼭 가기·1순위 반영 수도 3장의 기준을 따른다.

## 5. 계약

- `backend/candidate_results.py`: 항목의 `branch`는 선택 필드다. 있으면 `fromPlaceId`(카탈로그 ID, 자기 자신이 아님) · `reasonCode`(`shorter_route` | `original_unavailable`) · `savedMin`(`shorter_route`면 1~1440 정수, `original_unavailable`면 `null`)만 허용하고, `source`는 `selected`여야 한다. 다르면 저장하지 않는다.
- 웹 타입: `web/src/lib/shared-results-api.ts`의 항목 `branch?`에 위 필드를 포함하며 결과·일정 화면이 이를 읽는다.
- 예전 카탈로그(브랜드 정보 없음)와 데모 방에서는 아무것도 바뀌지 않는다.

## 6. 검증

- 엔진 테스트 `backend/engine/branch_placement.test.mjs` 15개: 휴무 대체·남은 영업일 우선·기다려도 배치 실패 시 재시도, 방문 목적과 제외 브랜드 존중, 이동 단축 수치, 교체 그룹 중복 방지, 구성원 지점 우선, 후보 3곳 상한, AI 후보와의 분리, 활동 시간에 맞춘 자리 수, 예전 카탈로그 호환을 확인한다.
- 서버 계약 테스트 `test_branch_field_is_optional_but_strictly_shaped`.
- 화면의 그룹 동등성·설명 조건은 `web/_test/experiment.test.ts`, `web/_test/shared-flow.test.ts`에서 확인한다. 전체 검사 수는 변경될 수 있으므로 해당 커밋의 실행 결과를 PR에 기록한다.
- 반복되는 하루 검사는 한 번의 계산 안에서 날짜와 **순서가 있는** 장소 ID 목록으로 재사용한다. 세 전략과 휴무 대체 재시도는 공유하되 다른 요청·AI 사전 계산·지붕 경로/기본 경로 계산 간에는 공유하지 않는다. 일정 배치 규칙과 검사 조건은 유지한다.

**주의**: 일정에 지점 있는 가게가 들어가면 대부분 지점이 바뀐다. 참가자는 자기가 고른 지점과 다른 지점을 보게 되므로, 화면의 "고른 곳 → 배치" 표시가 꼭 필요하다(혜인).
