# API 계약 조은 담당 검토 (2026-09-29)

대상: [서버 API 계약 PR #22](https://github.com/travel-recommender/gachilo/pull/22). 장소 데이터와 비용 단위만 검토했으며 윤진 담당 AI 출력 승인을 대신하지 않습니다.

- 원본은 16필드입니다. 계약 응답은 `cost`를 `cost_krw`로 바꾸고 `opening_hours_source`, `verified_at`을 제외하므로 기본 장소 필드는 14개입니다. ‘16개 그대로’라는 문구는 ‘16개 기반 공개 응답’으로 수정하는 것이 정확합니다.
- JPY 원본을 보존하고 API 경계에서 KRW로 변환하는 방향이 맞습니다. `1 JPY당 KRW`, 원 단위 사사오입, 환율 기준일·출처를 명시해야 합니다. 미확인 가격 null을 0으로 바꾸면 안 됩니다. 현재 어댑터는 환율을 환경변수로 받고 미설정 시 유료 가격을 null로 반환합니다.
- 쇼핑 구매비는 개인차 때문에 계산 대상에서 제외합니다. `cost_status=not_applicable_shopping`은 무료가 아닙니다. 카페·식사·입장권은 기준 메뉴·티켓의 가격이고 평균 총지출이 아닙니다.
- 실제 `area`는 행정구역(예: 大阪市中央区)입니다. 계약 예시의 ‘오사카성·텐마바시’ 같은 관광 권역은 별도 매핑이 필요합니다.
- `address`, `opening_hours`, `cost_krw`, `covered`, `website` 등은 null을 허용해야 합니다. 폐업/예약/지점 혼동 검토 상태를 프론트가 알 수 있어야 하므로 검증일만 숨기고 무조건 사용 가능한 장소처럼 노출하면 안 됩니다.
- 수집 데이터 `bag_load`는 0/1/2 상대 점수입니다. 기존 데모 엔진 `bagLoad`는 0~1로 정의되어 있어 연결 시 변환 또는 엔진 규칙 변경이 필요합니다. 현재는 두 데이터셋을 혼합하지 않습니다.
- 수집 데이터의 `covered`는 주요 공간 실내/지붕 여부입니다. 기존 데모의 아케이드 연결 여부와 의미가 다릅니다.
- `opening_hours`에는 요일·휴일·접수 마감이 있는 자유문장이 있으므로 단일 09:00~18:00로 단순 변환하면 안 됩니다.

현재 추가한 `/api/places`는 실제 150곳의 데이터 조회·통화 경계입니다. 기존 36곳 데모 계산, 인증, 단계, 결과 API를 계약 초안으로 전면 교체한 것은 아닙니다. 주소 2곳·영업시간 23곳 및 방문일별 검증이 남아 있어 이슈의 ‘150곳 일정 생성 투입 가능’ 완료 기준은 아직 충족하지 않습니다.
