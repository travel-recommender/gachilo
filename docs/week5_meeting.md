# 5주차 개인 작업 및 회의 메모

기준: [5주차 이슈](https://github.com/travel-recommender/travel-recommender/issues/1). 조은 담당 데이터·백엔드 구현과 연결 예제입니다.

## 완료한 구현
- OSM/Overpass 수집 스크립트, 원본, 정규화 후보 및 16필드 장소 스키마 저장.
- 오사카 150곳을 선정하고 카페 지점과 공식 출처 검토 기록을 반영. 전체 검토가 전체 검증 완료를 의미하지 않음.
- SQLite 기반 방 생성, 참여자 입력 저장·수정, 계산 결과 저장·조회 API.
- 저장된 전원 입력을 기존 추천 알고리즘에 전달하고, 입력 수정 시 이전 결과를 무효화.
- Next.js `/server-check` 연결 확인 화면과 fetch 모듈 추가. 기존 데모는 유지.

## 검증
- 데이터 회귀검사 7건 통과.
- 실제 HTTP 서버 통합검사 7건 통과: 입력·결과 저장, 재조회, 인증, 동시 입력, 실제 계산 및 변경 후 재계산.
- Next.js 정적 빌드와 타입검사 통과 (로컬 설치 의존성 기준).
- 실제 브라우저 클릭과 모바일 표시 검사는 도구의 브라우저 정책 확인 실패로 미실시.

## 회의에서 말할 내용
“오사카 장소 수집·정규화와 150곳 검토 자료를 정리했고, 방 생성부터 참여자 입력 저장, 일정 계산과 결과 조회까지 서버로 연결했습니다. 서버 테스트 7건과 화면 빌드는 통과했습니다. 지금 계산은 기존 36곳 시연 데이터이고, 다음에는 팀 화면의 두 단계 선택·초대 흐름과 연결하고 검토한 장소 데이터를 반영해야 합니다.”

## 팀과 연결할 항목
- 혜인: 기존 두 단계 화면의 store를 API로 전환. `/server-check`는 계약 확인용 단일 화면이며 기존 사용자 흐름 전환 완료를 뜻하지 않음.
- 윤진: 알고리즘·결과 형식 검토 및 AI 설명 연결. 현재 AI API 호출 없음.
- 6주차: 실제 초대·참여 인증, 재접속, 진행 상황 및 여러 기기 확인. 현 토큰 배부는 로컬 시험용.
- 장소 150곳의 누락 주소·영업시간, 운영 중단 표시, 비용·체류시간 정규화가 남음. 일정용 검증 완료 데이터로 취급하지 않음.
- 150곳의 비용 단위 JPY와 기존 시연 예산 KRW를 직접 혼합하지 않음.
- 백엔드는 로컬 전용이며 GitHub Pages에 배포되지 않음.
