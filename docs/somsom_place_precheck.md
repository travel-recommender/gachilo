# A/B/C 생성 전 솜솜AI 판정 대조

실제 장소의 기존 데이터 준비 상태와 방문일 운영 확인 결과를 일정 생성 전에 솜솜AI에 전달하여 서버 규칙의 판정과 대조합니다. AI는 외부 정보를 검색하거나 영업 사실을 독립적으로 검증하지 않으며, 후보 선택과 일정 생성의 최종 판단은 기존 서버 규칙이 담당합니다.

전달 정보는 날짜와 장소별 `dataReady`, `livePassed` 불리언뿐이며 장소명, ID, 개인 선택, 원문 출처와 인증 정보는 보내지 않습니다. 기존 운영 확인이나 예산 처리에 새로운 조건을 추가하지 않습니다. 운영 조회 실패 시 처리 정책의 변경은 별도 작업에서 통합합니다.

AI 응답이 서버 규칙과 일치하면 `source: somsom`, `status: matched`로 기록합니다. 키 누락, 시간 초과, 오류, 형식 오류, 응답 불일치 또는 입력 크기 제한 시 기존 서버 규칙으로 계속 진행하고 `source: rule`, `status: fallback`과 사유 코드를 기록합니다. 운영 정보 조회가 모의 실행이면 `source: mock`으로 구분합니다. 실제 Google 조회와 `AI_MOCK`을 함께 쓰면 AI 호출은 생략되고 `rule/fallback/unavailable`로 기록되어 키 누락 등과 로그만으로 구분되지 않습니다. 원문 응답은 저장하지 않습니다.

경로 표 준비와 판정 대조는 동시에 시작하지만, 장소 배치와 A/B/C 일정 계산은 대조가 끝난 후 시작합니다.

감사 기록에는 버전, 출처, 상태, 사유, 장소·날짜 수, 판정 수 및 입력 해시만 포함합니다. 세 전략에 동일한 대조 결과가 붙으며, 이 단계는 기존 후보를 변경하지 않습니다. 실제 호출은 지연 및 사용 비용이 발생할 수 있으므로 실험 적용과 운영 조회 정책 통합은 팀 검토 후 확인해야 합니다.
