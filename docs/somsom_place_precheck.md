# 일정 생성 전 솜솜AI 장소 검수

실제 장소 방의 순서는 **검증된 장소 데이터 + Google Places 영업 확인 → 솜솜AI 장소·날짜 검수 → 통과한 장소로 A/B/C 생성**이다. 완성된 세 일정을 AI에게 다시 보내는 기능은 아니다.

## 검수 범위

- 참여자가 담은 장소, 같은 브랜드의 교체 지점, 자동 추천 후보를 한 묶음으로 확인한다.
- 날짜별 자료 사용 가능 여부, 실시간 영업 확인 결과, 입장 마감이 포함된 운영 구간, 체류시간, 대표 비용과 그룹 예산을 전달한다.
- 동일 장소에서 날짜별 조건이 같으면 하나의 행으로 묶어 호출량을 줄인다. 세 전략이 동일한 검수 결과를 사용한다.
- 모델에는 이름·회원 ID·개인 선택 목록·인증정보·자유 형식 원문을 보내지 않는다. 그룹 예산과 숫자·불리언으로 정리한 후보 정보만 전달한다.
- 솜솜AI가 웹을 새로 검색하거나 미래의 영업을 보증하는 구조가 아니다. 최신 정보는 앞 단계의 Google Places 조회와 검증된 날짜 자료가 제공한다.

모델은 행별 사용 가능 여부만 JSON 불리언 배열로 반환한다. 서버가 동일 근거로 판정한 결과와 **모든 행이 일치해야** 검수가 완료된다. AI가 휴무·자료 미확인·체류 불가·개별 비용 초과 장소를 임의로 통과시키거나 근거 없이 제외하면 완료 처리하지 않는다.

통과한 후보로 일정 배치를 시작한 뒤에도 기존 서버 검사가 실제 방문 시각, 하루 누적 예산, 걸음·활동시간 한도, 제외 장소와 지점 교체 조건을 확인한다. 사전 검수의 개별 장소 비용 비교가 하루 전체 예산 검사를 대신하지 않는다. 쇼핑·교통·숙박 제외 등의 기존 비용 범위도 유지한다.

## 실패와 저장

- 실제 Google 조회를 사용하는 방은 `SOMSOM_API_KEY`와 정상 AI 응답이 필요하다. 키 누락, 12초 제한, 통신 실패, 잘못된 JSON, 근거와 불일치한 판정이면 후보를 게시하지 않고 재계산 안내를 반환한다.
- 한 번의 계산에서 사전 검수는 최대 한 번 호출한다. 최대 500개 조건 행/180KB 입력을 넘으면 호출 전에 자료량 제한 안내를 반환한다. 기존 빈자리 AI 추천 호출은 별개다.
- 오프라인 검사·모의 조회는 외부 호출 없이 `source: mock`으로 기록한다. 실제 AI 검수와 구분한다.
- 세 후보의 `planning.ai_precheck`에 버전, 검수 출처·시각, 검수/허용/제외한 장소·날짜 쌍 수와 전달 자료 SHA-256을 함께 저장한다. 원문 프롬프트·응답·키는 저장하지 않는다.
- AI 호출 실패 시 부분 후보를 저장하지 않는다. 계산 잠금 해제 후 같은 입력으로 재시도할 수 있다.

## 적용과 실험

PR #76의 실제 장소 서버 경로를 기반으로 한다. #76 이후 이 PR을 병합한다. 기존 저장 후보를 재검수한 것으로 표시하지 않으며, 새로 계산하는 후보에 적용된다. 동결된 실험에는 새 코드에 맞는 새 세션을 생성해야 한다. 기존 참가자 기록은 보존한다.

화면의 설명 있음/없음 배정, A/B/C 전략 순서, 장소 선택 조건은 이 변경에서 바꾸지 않는다. 장소 데이터 검증·사진·꼭 가기 개수 변경은 별도 작업이다.

검증: Node 24의 후보·지점 배치·실시간 조회·새 사전 검수 검사, Python의 HTTP 공동 후보 저장·조회·실패 후 재시도 검사, 웹 타입 검사. AI·Google 응답은 테스트 대체 응답을 사용하며 실제 유료 API나 Railway 실험 세션은 이 PR 검증에서 호출·변경하지 않았다.
