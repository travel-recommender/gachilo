# 캡스톤 프로젝트 주제안

2026.09.14 · 엄혜인, 윤진, 조은

---

## 1. 제목

**개인별 제약이 다른 그룹을 위한 공정성 기반 여행 일정 생성 및 설명 시스템**

> 친구들이 각자 가고 싶은 곳과 예산·체력을 비공개로 입력하면, 아무도 무리하지 않으면서 모두가 자기 몫을 챙기는 일정을 만들고 **왜 그렇게 됐는지 설명**해주는 서비스.

---

## 2. 문제 정의

여행을 계획하면 한 명이 일정을 도맡고 나머지는 "아무거나"라고 답한다. 그러다 현장에서 불만이 나온다. 너무 걷는다, 돈을 많이 쓴다, 가고 싶던 곳이 빠졌다.

미리 말하지 않는 이유는 **예산과 체력이 말하는 순간 개인의 형편과 상태가 드러나는 정보**이기 때문이다. 적게 쓰고 싶다고 하면 궁색해 보이고, 못 걷겠다고 하면 민폐 같다.

> 문제는 서로의 취향을 **모르는 것**이 아니라 **말할 수 없는 것**이다.

학술적으로는 **이질적 제약 하의 다자간 선호 취합 및 일정 계획 문제**로 정의된다. 참여자마다 예산 상한과 체력 한계가 다르고, 그룹 일정은 이를 동시에 만족해야 한다.

---

## 3. 경쟁 분석

**서비스** — Wanderlog, 트리플, Triply, Plotline은 모두 **협업 편집기**다. 공동 편집과 경로 최적화는 하지만, 의견이 갈리면 채팅으로 넘긴다. 예산·체력 차이는 다루지 않는다.

**연구** — 그룹 추천(GRS)과 여행 일정 설계(TTDP)는 각각 성숙했으나 공통된 가정이 있다.

| 기존 가정 | 본 연구 |
| --- | --- |
| 그룹 전체에 단일 예산·시간 제약 | **개인별로 다른 제약** |
| 그룹은 항상 함께 이동 | **부분 동행 허용 (코어/옵션)** |
| 이동 비용은 거리에만 의존 | **짐 무게 등 상태 의존적 비용** |
| 장소 선택까지만 | **선택 + 배치 통합** |
| 결과만 제시 | **설명과 What-if 제공** |

**방어 가능한 신규성** (우선순위순)
1. 부분 동행을 일정 생성에 반영 — 가장 독창적
2. 짐 무게 등 상태 의존적 이동 비용
3. 날씨·지하 네트워크 기반 쾌적 도보 (일본 도시 특화)

## 4. 시스템 아키텍처

```
1차 입력 (비공개)            빈 화면에서 검색으로 장소 5곳 (없으면 직접 추가)
   ↓
2차 입력 (비공개)            모두의 후보에서 5곳 · 꼭 1곳 · 거부 1곳
   ↓
조건 입력 (비공개)           하루 예산 · 하루 걸음 수 · 하루 활동 시간
   ↓
1단계  선택   공정성 기반 선호 취합 → 코어 / 옵션 분리
   ↓
2단계  배치   영업시간 · 개인 체력 · 짐 · 날씨 제약 하 동선 최적화
   ↓
3단계  설명   근거 문장 · 만족도 대시보드 · What-if
```

| 단계 | 담당 | 산출물 |
| --- | --- | --- |
| 선택 | 윤진 | 어디를 갈지, 누가 함께 갈지 |
| 배치 | 조은 | 어떤 순서로, 언제 |
| 설명 | 혜인 | 왜 이렇게 됐는지 |

**규칙과 AI의 역할 분리** — 장소 선정과 순서는 규칙·최적화가 정한다. AI는 합의 조건에 맞는 장소를 남은 자리에 채우는 것, 빈 시간 채우기, 설명 문장 생성, 대안 제시를 담당한다. AI가 임의로 결정하면 사용자가 결과를 믿지 않고 심사에서도 방어가 어렵다.

## 5. 핵심 알고리즘

### 5-1. 예산 — 하드 제약

각자의 상한 중 최솟값을 그룹 제약으로 설정. 한 명이라도 감당 못 하는 후보는 제외한다.
상한은 **하루 예산**으로 받아 일수를 곱해 여행 예산으로 환산한다(총액은 기간에 따라 감이 달라져 답하기 어렵다).
체력도 같은 이유로 **하루 걸음 수**로 받아 보폭 70cm 기준으로 km로 환산한다.

```
B_group = min(B_1, ..., B_n),  B_i = (하루 예산_i) × 일수
```

### 5-2. 선호 취합 — 세 전략 비교

| 전략 | 목적함수 | 특징 |
| --- | --- | --- |
| 평균 | max Σ sat_i | 단순하나 아무도 만족 못 할 수 있음 |
| 최소 불만 | max ( min sat_i ) | 크게 싫어하는 선택지 배제 |
| **공정성** | min Var(sat_i) / Gini | 개인별 만족도 편차 최소화 |

주 가설: **공정성 전략이 평균 전략보다 그룹 만족도와 균등성을 동시에 높인다.**

### 5-3. 개인 만족도

```
sat_i = w1·(내 선택 반영률) + w2·(내 '꼭' 반영 여부)
      + w3·(예산 여유도)   + w4·(체력 여유도)
      - w5·(거부 위반)
```

### 5-4. 부분 동행 — 코어 / 옵션

기존 연구는 그룹이 항상 함께 이동한다고 가정하나, 실제로는 갈라진다.

- **코어** — 전원의 제약을 만족하는 장소. 다 같이 이동
- **옵션** — 일부만 만족하는 장소. 원하는 사람만, 자유시간에

옵션을 허용하면 해 공간이 넓어져 제약이 이질적일수록 만족도가 올라간다.

### 5-5. 짐 무게 — 상태 의존적 비용

```
cost(i → j) = dist(i, j) × (1 + α · load)
load = 누적 쇼핑 부피
```

최적해가 자연스럽게 쇼핑을 하루 뒤쪽이나 숙소 근처로 배치한다.

### 5-6. 쾌적 도보 — 날씨 · 실내외

일본 주요 도시는 지하상가·아케이드 네트워크가 발달해 있다. (우메다 지하상가, 신사이바시스지, 난바 워크)

```
weight(경로) = 거리 × (1 + β · 노출도 × 강수확률)
```

강수 확률이 높거나 체력 한계가 낮은 구성원이 있으면 지붕 있는 경로를 우선한다.

## 6. 데이터 확보

### 장소 — 오사카 1개 도시, 120~150곳 직접 구축

| 필드 | 출처 |
| --- | --- |
| 이름·좌표·카테고리 | OpenStreetMap (Overpass API) |
| 영업시간 | OSM `opening_hours` + 수작업 검증 |
| 실내/지하 연결 | OSM `indoor` / `covered` / `tunnel` |
| 체류시간·예상 비용 | 수작업 (요금표·객단가 조사) |
| 인기도 | Google Places 평점·리뷰 수 |

일본은 OSM 품질이 높아 영업시간·지하 연결을 상당 부분 자동 수집할 수 있다. 150곳은 3인이 2~3주에 구축 가능하다.

### 이동·날씨

OSRM(오픈소스 라우팅) 또는 Google Directions API, Open-Meteo(무료).

### 선호 — 평가용 데이터 확보가 핵심

**(a) 사용자 실험** — 4~5명씩 4개 그룹(16~20명). 실제 입력 후 세 전략으로 생성된 일정 3개를 블라인드로 평가.

**(b) 시뮬레이션** — 실험 응답에서 선호·예산·체력 분포를 추정해 **가상 그룹 1,000개 이상** 생성, 전략별 지표를 통계 비교.

사용자 실험만으로는 검정력이 부족하다. 시뮬레이션을 붙여야 논문으로 발전한다.

## 7. 평가 설계

### 연구 질문

> 개인별 예산·체력 제약이 이질적인 그룹 여행에서, **공정성 기반 취합**과 **부분 동행 허용**이 그룹 만족도와 만족도 편차에 어떤 영향을 주는가?

**2 × 2 요인 설계**

| | 전원 동행 | 부분 동행 허용 |
| --- | --- | --- |
| 평균 취합 | A (기준선) | B |
| 공정성 취합 | C | D |

### 지표

평균 만족도 · 최소 만족도 · 만족도 편차(std·Gini) · 제약 위반율 · '꼭' 반영률 · 설명 수용도(5점)

### 가설

- **H1** 공정성 취합은 평균 취합보다 최소 만족도를 높인다
- **H2** 공정성 취합은 평균 취합보다 만족도 편차를 낮춘다
- **H3** 부분 동행 허용은 제약이 이질적일수록 평균 만족도를 높인다
- **H4** 설명을 제공하면 동일한 일정이라도 수용도가 높아진다

H4가 교수님이 말씀하신 "추천한 이유"에 해당한다.

## 8. 범위

**대상** — 한국인의 오사카 여행. 지하상가가 발달해 쾌적 도보를 적용하기 좋고 한국인 리뷰가 풍부하다. 한 도시를 깊게 다룬 뒤 도쿄·후쿠오카로 확장하는 구조로 설계한다.

| 기능 | 우선순위 |
| --- | --- |
| 방 생성(기간·동행자)·초대 | MVP |
| 1차 검색으로 장소 5곳 찾기, 없으면 직접 추가 | MVP |
| 2차 모두의 후보에서 5곳 선택(꼭/거부) | MVP |
| 조건 입력 — 하루 예산·하루 걸음 수·활동 시간 | MVP |
| 비공개 입력·참여 현황 | MVP |
| 규칙 기반 합의 일정 생성 (3전략), 코어/옵션 분리 | MVP |
| 영업시간 제약, 지도 기반 이동 거리·시간 | MVP |
| AI 장소 추가·빈칸 채우기·설명 생성, 만족도 대시보드 | MVP |
| 경비 정산 | MVP |
| 짐 무게 재배치, 날씨 쾌적 도보, What-if | 2차 |
| 역할별 가중치, 틈새 스팟, 도시 확장 | 3차 |

**재사용 자산** — 취향 슬라이더와 트레이드오프 엔진, 5개 도시 106곳 장소 데이터(좌표·리뷰·비용), 일정·지도·편집 화면, 그룹 초대, n빵 정산.
