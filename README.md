# travel-recommender

동덕여자대학교 빅데이터(캡스톤 디자인) · 3인 팀

**개인별 제약이 다른 그룹을 위한 공정성 기반 여행 일정 생성 및 설명 시스템**

> 친구들이 각자 가고 싶은 곳과 예산·체력을 **비공개로** 입력하면,
> 아무도 무리하지 않으면서 모두가 자기 몫을 챙기는 일정을 만들고
> **왜 그렇게 됐는지 설명**해주는 웹 서비스.

이 저장소는 **본 프로젝트**입니다. 프로토타입과 기획 문서는
[travel-recommender_prototype](https://github.com/travel-recommender/travel-recommender_prototype)에 있습니다.

## 협업 규칙

### main은 직접 푸시 금지

**main에 직접 푸시할 수 있는 사람은 혜인 한 명뿐입니다.** 나머지는 예외 없이
브랜치를 따서 PR로 올립니다. 저장소 설정으로 강제돼 있어 규칙을 어기면 푸시가 거부됩니다.

```bash
git switch -c feat/place-schema   # 브랜치 생성
# 작업 후
git push origin feat/place-schema # PR 생성
```

- 브랜치명: `<타입>/<요약>` 예) `feat/room-api`, `fix/map-marker`, `docs/plan`
- 커밋 메시지: 한 줄 명령형. 예) `장소 데이터 스키마를 추가한다`
- PR은 **최소 1인 리뷰** 후 머지합니다.
- 비밀값(API 키, 계정 정보)은 커밋하지 않습니다. `.env`는 gitignore합니다.
  **AI API 키는 서버 환경변수로만 둡니다. 프론트엔드에 넣지 않습니다.**

### 진행 상황은 이슈로 봅니다

아래 로드맵의 각 항목이 이슈로 등록돼 있습니다. 작업을 시작할 때
**본인을 assignee로 등록**하세요. assignee가 비어 있으면 아직 아무도 안 잡은 일입니다.
