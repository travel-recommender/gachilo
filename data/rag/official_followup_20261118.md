## 적용·검증

Node **24 이상**, Python **3.10 이상**이 필요하다. Node 16은 `.ts` 직접 import를 지원하지 않는다.

이 PR은 #82의 자료 관리 기능 위에 만든 **검토 자료팩**이다. 현재 runtime manifest·운영 프로필·실험 묶음·실행 서버는 변경하지 않는다. 다음 명령은 원본 값과 출처가 그대로인지 검사한 뒤 **새 폴더**에만 후보 카탈로그와 보고서를 생성한다.

```sh
python3 scripts/materialize_visit_evidence.py \
  --catalog data/final/osaka_catalog_20261112.json \
  --out .local/rag-followup-review
python3 -m unittest discover -s scripts -p test_materialize_visit_evidence.py
node --test scripts/test_official_rag_followup.mjs
```

검토자가 병합 후 사용할 최신 카탈로그를 `--catalog`로 명시한다. 지점 정보·값·기존 출처가 달라졌으면 중단하고 그 항목을 다시 대조한다. 불일치 시 아래 재검토 절차를 따른다. 해시를 임의 갱신해 통과시키지 않는다. 같은 자료팩 중복 적용이나 기존 출력 폴더 덮어쓰기도 거부한다.

- `catalog.json`: 기존 영업시간·가격·좌표·브랜드·선택 가능 상태는 그대로. 확인된 항목의 출처만 갱신하고 이전 출처는 `previous`에 보존.
- `review-report.json`: 입력/출력 해시, 범위, 부분 확인·조회 실패 목록. 상태는 `prepared_not_activated`.
- `review.visit_evidence`: 연도를 확인한 HEP 휴무 1건만 정확한 날짜의 근거로 추가. 엔진 프로필의 휴무는 이미 같은 값이며 수정하지 않음.

#76·#82와 최종 데이터 변경이 병합된 뒤, 새 코드·새 자료 기준으로 실험 묶음을 재생성하고 전체 일정·지도·설명 표시를 점검한다. 원래 실험 묶음에 새 파일을 덮어쓰지 않는다. 자료 관리 경고는 #82의 상세 근거 영역에 남는다. 기존 날짜별 방문 조건 배지의 예약·검토 기간 밖·실시간 실패 안내는 유지한다. HEP 입점사 URL은 `reviewed_urls`로 보조 출처를 구분하고, 운영사 URL만 공식 직접 근거로 표시한다.


## 병합 후 해시가 달라졌을 때

전체 `place` 해시 검사는 유지한다. 이름·좌표·지점 식별·브랜드 변경도 잘못된 장소에 근거를 붙일 수 있으므로 자동 해시 갱신 명령을 제공하지 않는다.

1. 오류에 나온 place ID의 원본(이 팩 기준 카탈로그)과 최신 카탈로그를 비교하고, 바뀐 필드와 값·원인 커밋을 PR에 기록한다. 기존 source 변경도 별도로 비교한다.
2. **시간·가격·주소·좌표·지점 식별·운영 상태가 바뀐 경우** 공식 출처에서 같은 지점인지와 해당 항목을 다시 확인한다. 실제 확인일·expected_value·기존 출처 해시·제한 사항을 함께 갱신한 새 날짜/버전 팩을 만든다.
3. 태그·번역 같은 비운영 필드만 바뀌었어도 같은 지점·운영 값·기존 출처가 유지되는지 검토자가 확인한다. 그 비교 근거를 남긴 뒤 새 버전 팩의 identity 해시만 재계산할 수 있다. **웹을 다시 확인하지 않았다면 checked_at은 원래 날짜 그대로** 둔다.
4. `expected_source_sha256`이 다르면 이전 확인 기록을 삭제하지 않고 양쪽 근거를 대조한다. 재검증하거나 이미 적용된 항목을 새 팩에서 제외한다. previous 이력을 보존한다.
5. 새 팩은 테스트와 팀 재리뷰를 거친 뒤 NEW 출력 폴더에 적용한다. 이전 팩·동결 실험 묶음은 그대로 보존한다.

## 출력 실패 복구

두 파일을 같은 부모의 임시 폴더에 완성한 뒤 배타적으로 새 출력 디렉터리를 만들고 게시한다. 쓰기·게시 중 예외는 생성한 파일을 정리하며 기존 경로(실행 도중 다른 작업이 만든 경로 포함)는 덮어쓰지 않는다. 디스크 전체 장애나 강제 종료(SIGKILL)는 정리를 막을 수 있으므로, 비정상 종료 후 남은 폴더를 정상 결과로 쓰지 않고 보고서의 input/output 해시와 파일 쌍을 확인한다. 확인되지 않은 폴더는 보존하고 새 출력 경로로 재실행한다.
